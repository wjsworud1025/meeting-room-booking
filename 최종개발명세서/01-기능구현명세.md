# 기능 구현 명세 v1.1

작성일: 2026-09-22 · 상위 문서: [최종 개발명세서](./00-최종개발명세서.md)

이 문서는 사용자에게 제공할 동작과 처리 결과를 정의한다. 데이터베이스·API·서버 구성은 [시스템 구현 명세](./02-시스템구현명세.md)를 따른다.

## 1. 용어와 공통 원칙

| 용어 | 의미 |
| --- | --- |
| 학생 | 관리자가 등록하고 활성화한 교육생 |
| 최초 신청자 | 예약을 처음 만든 학생. 이후 책임 이전과 무관하게 변경되지 않음 |
| 책임자 | 예약 시간·방 변경과 전체 취소 권한을 가진 현재 참여자. 최초에는 신청자 |
| 수락자 | 참여에 동의한 학생. 신청자는 처음부터 수락자 |
| 대기자 | 초대받았으나 아직 수락·거절하지 않은 학생 |
| 확정 최소 인원 | 예약을 확정하기 위해 필요한 실제 수락자 수 |
| 판정시각 | 서버가 요청 처리 순서를 확보한 뒤 확인한 시각 |
| 기준 명단 | 처음 확정될 때의 수락자 명단. 이후 이탈해도 수정하지 않음 |
| 이용 예정 명단 | 예약 시작 시각의 수락자 명단. 실제 출석을 의미하지 않음 |

정원은 수락자와 대기자의 합으로 계산하고, 확정 최소 인원은 수락자만 계산한다. 색상과 글자를 함께 사용해 상태를 표시한다. 사용자가 요청을 전송했거나 슬랙이 접수했다고 해서 예약이 확보된 것으로 표시하지 않는다.

규칙과 오류 안내는 학생이 다음에 할 수 있는 행동을 포함한다. 일상 예약에 관리자 승인을 요구하지 않는다. 서버가 확인한 결과가 최종 상태다.

## 2. F-01 계정·로그인

| 항목 | 요구사항 |
| --- | --- |
| 가입 대상 | 등록된 학생과 F-16 절차로 초대된 관리자. 공개 회원가입 없음 |
| 로그인 | 이메일로 받은 일회용 코드로 인증 |
| 역할 | 학생, 기관 관리자 두 역할 |
| 계정 분리 | 계정 하나에 역할 하나. 관리자 전용 계정은 학생 예약·초대 대상에서 제외하고 학생 계정으로 자동 전환하지 않음 |
| 로그인 진입 | 학생 /login, 관리자 /admin/login. 인증 방식은 공유하되 로그인 후 역할에 맞는 화면으로 이동 |
| 비활성·기수 종료 | 비활성 학생은 기존 로그인 상태가 있어도 업무 기능 사용 불가 |
| 이용 제한 | 조회와 본인 상태 확인·정정 요청은 허용. 예약 신청·수락·추가 초대는 제한 |
| 슬랙 연결 | 로그인한 웹 계정과 본인의 슬랙 계정을 일회용 연결 절차로 연결. 이름만으로 자동 연결하지 않음 |

같은 기관에서 한 학생이 중복 계정으로 등록되지 않도록 관리한다. 관리자는 명단 일괄 등록·개별 추가·계정 정정을 제공한다. 인증 실패 안내로 다른 학생의 등록 여부를 불필요하게 공개하지 않는다.

## 3. F-02 공개 정보와 권한

| 정보 | 다른 등록 학생 | 해당 예약 대기자 | 해당 예약 수락자 | 관리자 |
| --- | --- | --- | --- | --- |
| 방·시간·상태·책임자 | 가능 | 가능 | 가능 | 가능 |
| 수락·대기 인원 수 | 가능 | 가능 | 가능 | 가능 |
| 수락자 이름 | 불가 | 가능 | 가능 | 가능 |
| 다른 대기자 이름 | 불가 | 불가 | 가능 | 가능 |
| 기준·이용 예정 명단 및 변경 이력 | 불가 | 불가 | 일반 화면 비노출 | 가능 |
| 학생 연락처·제재·신고 내용 | 불가 | 불가 | 타인 정보 불가 | 업무상 필요한 범위 |

초대 후보 선택에서는 활성 학생의 이름·기수·반 등 식별에 필요한 최소 정보를 보여준다. 다른 모임에 참여 중인 사람의 비공개 예약 정보를 초대 후보 화면에 노출하지 않는다. 공개 전광판·비로그인 시간표는 제공하지 않는다.

관리자 계정은 학생 검색·예약 참여 대상이 아니다. 관리자는 운영 화면에서 예약을 관리하며 관리자 역할만으로 학생 예약을 신청하거나 수락할 수 없다. 같은 사람이 교육생으로도 이용해야 하면 별도 이메일로 학생 계정을 등록한다. 같은 이메일에 두 역할을 부여하거나 화면 전환만으로 역할을 바꾸지 않는다.

| 항목 | 기본값·동작 |
| --- | --- |
| 초기 시설 | 4인실 4개, 8인실 1개 |

| 시간대 | Asia/Seoul |

| 주말·공휴일 | 폐관. 날짜·방·시간별 관리자 예외 개방 가능 |
| 예약 가능 날짜 | 기관 현지 날짜 기준 오늘부터 3일 뒤까지. 매일 00:00에 새 날짜 개방 |
| 예약 단위 | 시작·종료 30분 단위, 이용시간 30·60·90·120분 |

10일에는 13일 이용분까지 신청할 수 있다. 21:00~21:30 예약은 가능하고 21:30을 넘기는 예약은 불가하다. 이미 시작한 시간 구간의 남은 부분을 새로 예약하지 않는다.

시간 구간은 시작 포함·종료 제외다. 18:00~19:00과 19:00~20:00은 개인 일정상 겹치지 않는다. 같은 모임의 1시간 간격은 별도 검사한다. 하나의 예약은 열린 운영 구간 안에 온전히 들어가야 하며 중간 폐관 시간을 가로지를 수 없다.

공휴일·예외 개방은 관리자가 확인·관리한다. 시설 전체 휴관이 방별 개방보다 우선하며 전체 휴관을 해제하기 전에는 방별 예외로 이용할 수 없다.

## 5. F-04 시간표·내 예약·화면

| 화면 | 제공 내용·행동 |
| --- | --- |
| 전체 시간표 | 날짜 선택, 방 이름·정원, 운영 구간, 빈 시간, 예약 상태. 빈 구간 선택 시 신청 폼 |
| 신청 화면 | 선택된 방·시간, 길이, 초대 대상, 최소 인원·정원·마감 안내. 모임명 입력 없음 |
| 예약 상세 | 방·시간·책임자, 수락/대기 인원, 권한에 따른 명단·행동, 남은 기한 |
| 내 예약·초대 | 응답할 초대, 예정 예약, 인원 보충 필요, 취소·종료 이력 |
| 문제 신고 | 예약 연결, 미사용·시설 문제·기타 유형, 짧은 설명, 처리 결과 |

데스크톱은 같은 시간축에서 회의실들을 비교한다. 모바일은 날짜 선택과 방별 세로 목록을 사용한다. 클릭·키보드로 신청할 수 있어야 하며 드래그를 필수로 요구하지 않는다.

화면은 정상 연결 상태에서 변경을 5초 이내 반영하는 것을 목표로 한다. 본인의 변경 직후에는 즉시 최신 상태를 확인한다. 연결이 끊기면 마지막 확인 시각을 표시하고 오래된 시간표만으로 성공을 판단하지 않는다.

| 표시 상태 | 의미 |
| --- | --- |
| 예약 가능 | 해당 구간에 유효 점유 없음 |
| 예약중 | 최초 최소 인원 모집. 기한 표시 |
| 인원 보충중 | 확정 후 최소 인원 미달. 최초 부여한 보충 기한 표시 |
| 예약 확정 | 최소 인원 충족, 시작 전 |
| 이용 시간 도래 | 시작 이후·종료 이전. 실제 출석 확인을 의미하지 않음 |
| 종료 / 취소 | 종료시각 도달 또는 사유 있는 취소·자동 해제 |

## 6. F-05 예약 신청과 임시 확보

입력은 방, 시작·종료, 초대할 학생이다. 신청자는 자동 수락자로 포함되며 자기 자신을 중복 초대하지 않는다. 신청 시 최소 인원을 채울 수 있는 수만큼 다른 학생을 지정해야 한다.

| 검사 항목 | 성공 조건 |
| --- | --- |
| 학생 상태 | 활성 학생이며 이용 제한·신규 신청 제한 기간이 아님 |
| 시간·시설 | 예약 창·운영시간·단위·최대 이용시간 충족, 시작 전 |
| 방 점유 | 같은 방에 시간이 겹치는 유효 예약 없음 |
| 신청자 일정 | 신청자 본인의 수락된 다른 예약과 겹치지 않음 |
| 모집 건수 | 최초 신청자 기준 예약중·인원 보충중 예약이 현재 없음 |
| 초대 | 활성 학생, 중복 없음, 수락자와 대기자 합이 정원 이하 |

성공하면 방을 임시 확보하고 예약중으로 표시한다. 기한은 신청 판정시각 + 10분과 이용 시작시각 중 빠른 시각이다. 기한이 지나거나 같은 시각에 도달하면 수락할 수 없다. 화면의 카운트다운이나 기기 시각은 우선권 근거가 아니다.

동시에 같은 방을 신청하면 서버에서 먼저 확보한 한 건만 성공한다. 나머지는 방을 다시 선택하도록 안내한다. 신청자 1명만 수락한 상태로 같은 모임 비율을 판정하지 않는다.

## 7. F-06 초대·수락·거절

| 행동 | 처리 |
| --- | --- |
| 초대 | 시작 전 책임자·수락자가 활성 학생을 초대. 대기자도 정원 차지 |
| 수락 | 초대 당사자만 가능. 활성·제한 여부, 유효 기한, 정원, 개인 일정과 필요한 공정성 검사를 통과해야 반영 |
| 확정 | 수락으로 최소 인원에 도달하고 공정성 검사를 통과하면 즉시 확정 |
| 거절 | 대기 당사자가 거절하면 자리 해제 |
| 대기 초대 취소 | 책임자는 전체 대기 초대, 수락자는 본인이 보낸 대기 초대만 취소 가능 |
| 재초대 | 이전 초대가 종료된 학생을 새로 초대할 수 있음. 이전 초대의 버튼은 효력 없음 |
| 남은 초대 | 확정 후에도 시작 전까지 유효. 시작 시 미응답 초대 만료 |

대기 초대는 초대받은 학생의 개인 시간을 점유하지 않는다. 해당 학생이 다른 예약을 이미 수락했더라도 초대 자체는 가능하지만 충돌하는 수락은 거절한다. 다른 예약의 참여를 자동으로 취소하지 않는다.

최초 모집에서 최소 인원 미만인 중간 수락은 개인 일정 등 기본 검사를 통과하면 반영한다. 최소 인원을 채우는 수락에서 최종 공정성을 검사한다. 인원 보충 과정에서도 최소 인원 미달 후보 명단 자체는 비율 검사에서 제외하고, 재확정할 때 전체 후보 명단을 검사한다. 보존된 기준 명단은 유지한다.

수락 실패 시 해당 수락만 반영하지 않고 이전 예약과 기한을 유지한다. 실패한 초대는 기한 내 다른 시간으로 예약이 변경되는 등 조건이 바뀌면 다시 응답할 수 있다. 이미 처리된 같은 응답은 중복 인원으로 계산하지 않는다.

## 8. F-07 독점 방지·개인 일정

### 같은 모임과 시간 간격

`같은 모임 = 공통 인원 수 / 두 명단 중 작은 명단 인원 수 > 50%`

정확히 50%이면 다른 모임으로 본다. 같은 모임이면 시간이 겹치거나 앞 예약 종료부터 뒤 예약 시작까지 60분 미만일 때 새 확정·수락·변경을 거절한다. 신청 순서와 관계없이 시간상 앞뒤 예약을 검사한다. 방·신청자를 바꾸어도 적용한다. 30분만 이용했거나 다른 방이 비어 있어도 같은 간격을 적용한다.

| 비교 대상 | 판정 명단 |
| --- | --- |
| 한 번도 확정되지 않은 최초 예약중 | 모임 비교 대상에서 제외 |
| 시작 전 확정·인원 보충중 | 기준 명단 + 현재 수락자 명단. 현재 명단이 최소 인원 미달이면 현재 명단만 제외 |
| 시작 후·종료 예약 | 기준 명단 + 이용 예정 명단 |
| 취소·자동 해제 | 모임 비교 대상에서 제외 |

두 예약 사이의 유효한 명단 조합 중 하나라도 기준을 초과하면 같은 모임이다. 자신과 자신을 비교하지 않는다. 시간상 충분히 떨어진 예약은 비교하지 않는다.

| 발생 행동 | 검사할 후보 명단과 결과 |
| --- | --- |
| 최초 확정 | 최소 인원을 채운 후보 수락 명단. 통과 시 이를 기준 명단으로 보존 |
| 추가 수락·보충 | 최소 인원을 충족하는 수락 후 전체 명단과 보존된 기준 명단을 검사. 실패한 수락만 거절 |
| 시간·날짜·방 변경 | 기준 명단과 유효한 현재 명단을 변경된 조건으로 검사 |
| 본인 이탈 | 이탈 허용. 인원 축소로 중복 비율이 높아졌다는 이유만으로 이미 확정된 다른 예약을 소급 취소하지 않음 |
| 시작 | 현재 수락자 명단을 이용 예정 명단으로 한 번 고정. 출석 확인으로 취급하지 않음 |

첫 확정 명단은 재확정·책임 이전·예약 이동 때 새로 만들지 않는다. 먼저 확정된 유효 예약은 나중 요청 때문에 취소하지 않는다. 명단 축소로 유지된 기존 예약도 이후 새 수락·변경 요청에는 최신 판정을 적용한다.

### 개인 일정

신청자와 수락자는 시간이 겹치는 둘 이상의 예약에 참여할 수 없다. 대기 상태는 제외한다. 과거 판정 명단에만 남아 있는 이탈자는 개인 시간 점유에서 제외한다. 다른 구성원의 모임에 시간 충돌 없이 참여하는 것은 허용한다. 개인별 하루 총 이용시간과 같은 모임의 하루 총량 제한은 두지 않는다.

실제 출석을 확인하지 않으므로 등록 명단과 실제 이용자의 차이를 자동 판별하지 않는다. 반복적인 허위 등록이나 점유는 F-11 신고·관리자 확인으로 처리한다.

## 9. F-08 참여 이탈·인원 보충·신규 신청 제한

학생은 시작 전에 본인 참여를 취소할 수 있다. 책임자는 F-10에 따라 책임을 이전한 뒤 이탈하거나 전체 예약을 취소한다. 수락자를 책임자·다른 참여자가 강제로 제외할 수 없다.

| 상황 | 처리 |
| --- | --- |
| 이탈 후 최소 인원 이상 | 확정 유지 |
| 처음 최소 인원 미달 | 인원 보충중으로 전환. 첫 미달 판정시각 + 10분과 시작시각 중 빠른 시각을 보충 마감으로 부여 |
| 마감 전 보충 완료 | 공정성·일정 검사 후 확정 복귀. 원래 보충 마감 기록 유지 |
| 다시 인원 미달 | 첫 보충 마감 재사용. 이미 지났으면 즉시 취소 |
| 기한 내 보충 실패 | 자동 취소하고 방·개인 점유 해제 |
| 같은 최초 신청자의 다른 예약이 이미 모집중·보충중 | 나중에 인원 미달이 발생한 예약을 자동 취소 |

모집·보충 기한은 날짜·시간 변경으로 늘어나지 않는다. 시작시각을 더 앞당기면 마감도 그 시각을 넘을 수 없다. 인원 보충은 최소 인원에 도달할 수 있는 초대 교체를 허용하되 정원을 초과할 수 없다.

| 취소 원인 | 최초 신청자의 신규 신청 제한 |
| --- | --- |
| 최초 모집중 자진 취소 | 취소 판정시각부터 10분 |
| 모집·보충 기한 만료 | 원래 마감시각부터 10분. 늦게 처리됐다고 제한을 늦춰 시작하지 않음 |
| 보충 재부여 불가·모집중 중복으로 즉시 자동 취소 | 즉시 취소 원인이 발생한 판정시각부터 10분 |
| 최소 인원을 충족한 확정 예약의 정상 사전 전체 취소 | 제한 없음 |
| 보충중 자진 전체 취소 | 취소 판정시각부터 10분. 보충 실패 제한을 취소 버튼으로 우회하지 않음 |
| 관리자 시설 사유 취소 | 제한 없음 |

신규 신청 제한 중에도 다른 사람의 초대 수락은 가능하다. 여러 제한이 겹치면 더 늦은 종료시각까지 적용하며 계정 이용 제한과 구분한다.

## 10. F-09 시간·날짜·방 변경과 전체 취소

| 행위 | 현재 책임자 | 일반 수락자 | 관리자 |
| --- | --- | --- | --- |
| 시작 전 시간·날짜·방 변경 | 가능 | 불가 | 가능, 사유 기록 |
| 시작 전 전체 취소 | 가능 | 불가 | 가능, 사유 기록 |
| 시작 전 수락자 제외 | 불가 | 불가 | 가능, 최소 인원 처리 |
| 시작 후 추가 초대·수락·학생 이탈·전체 취소 | 불가 | 불가 | 학생 행동으로 대행하지 않음. 별도 관리자 조치 사용 |
| 시작 후 예약 취소·구성원 정정 | 불가 | 불가 | 가능, 사유 기록 |
| 시작 후 방·시작·종료 시간 수정 | 불가 | 불가 | 제공하지 않음 |

변경된 시작시각도 미래여야 한다. 운영시간·예약 창·최대 길이·단위·새 방 정원·대기 인원·개인 일정·공정성을 모두 검사한다. 작은 방으로 옮겨 수락자와 대기자 합이 정원을 넘으면 변경을 거절한다.

새 방의 최소 인원은 수락자로 충족해야 확정 상태를 유지한다. 이미 확정된 예약을 더 큰 방으로 이동해 최소 인원에 미달하게 되는 변경은 거절한다. 최초 모집중·보충중 예약은 초대 가능한 수와 새 정원이 적합하면 변경할 수 있으나 원래 마감은 유지한다. 변경 결과 수락자가 새 최소 인원에 도달하면 공정성 검사 후 확정한다.

성공하면 이전 공간을 해제하고 새 조건을 반영한다. 기존 수락은 유지하고 재수락은 요구하지 않는다. 변경 전 요약과 영향을 받는 인원을 보여주며, 성공 후 수락자·대기자에게 전후 내용을 알린다. 변경 실패 시 방·시간·구성원·기한 모두 이전 상태를 유지한다. 시간 경과에 따른 정당한 만료는 예외다.

시작 후 학생 조기 종료는 없다. 관리자 취소로 방이 비어도 이미 시작한 구간을 새로 신청할 수 없으며 다음 미래의 예약 단위 시작부터 신청한다. 관리자 구성원 정정은 수락 상태와 점유를 맞추되 기준·이용 예정 명단을 덮어쓰지 않고 별도 사유를 남긴다. 실제 출석 인증으로 표시하지 않는다.

관리자 구성원 조치는 수락자 제외와 정정 메모를 기본으로 한다. 다른 학생을 동의 없이 수락자로 추가하는 기능은 제공하지 않는다. 시작 전에 새 참여자를 넣어야 하면 일반 초대·본인 수락 흐름을 사용한다.

## 12. F-11 관리자 운영·신고·이용 제한

| 영역 | 기능 |
| --- | --- |
| 학생 | CSV 미리보기·유효 행 등록, 개별 추가, 비활성화, 기수 확인 |
| 관리자 계정 | 학생 관리와 분리된 메뉴. 관리자 목록·초대·초대 취소·재발송·비활성화·재초대·관리 이력. F-16 적용 |
| 예약 | 조회, 시작 전 변경, 취소, 구성원 정정, 영향과 사유·처리자 이력 |
| 시설 | 방 추가·수정·비활성화, 휴관·예외 개방, 영향 예약 사전 조회 |

| 이용 제한 | 확인된 당사자·사유·시작·종료·해제·정정 요청 기록 |

비활성화 전에 미래 참여·초대·책임 예약 영향을 보여준다. 책임 이전이 완료된 예약은 유지하고, 이전되지 않은 책임 예약은 비활성화 실행 시 취소한다. 다른 미래 참여와 초대는 제거하고 최소 인원 규칙을 적용한다. 여러 예약에서 발생하는 영향은 실행 전 최종 상태로 미리 보여준다.

학생 CSV·개별 등록·학생 비활성화·이용 제한·기수 일괄 종료는 학생 계정만 대상으로 한다. 관리자 계정은 학생 명단에 나타나지 않으며 학생용 처리에 이메일이나 식별자를 직접 입력해도 변경되지 않아야 한다.

시설 휴관은 영향을 확인한 뒤 취소 또는 시작 전 다른 방 이동으로 처리한다. 이동도 정원·개인 일정 등 기본 규칙을 충족해야 한다. 관리자가 특별히 중복 예약을 강제하는 기능은 없다. 시작된 예약의 시설 문제는 취소로 처리한다.

신고 수만으로 자동 제재하지 않는다. 관리자가 허위 참여 등록·반복 미사용·반복 임시 확보를 확인한 경우 처음에는 안내, 안내 후 재발 시 24시간, 추가 재발 시 3운영일 이용 제한을 기본값으로 제공한다. 사유·기간을 당사자에게 알리고 정정 요청 창구를 둔다. 확인되지 않은 다른 구성원까지 일괄 제재하지 않는다.

3운영일은 처리 시각 이후 시설 공통 운영 구간이 남아 있는 날짜부터 세 개의 운영일로 계산하며, 세 번째 날짜의 공통 운영 종료시각까지다. 시설 전체 휴관일은 제외한다. 관리자 화면에서 실제 시작·종료를 미리 보여주고 사유를 남겨 기간을 조정할 수 있다.

이용 제한 시작 시 당사자의 미래 예약 참여·대기 초대를 제거하고 책임 이전·최소 인원 처리를 적용한다. 이미 시작된 예약에 대한 개입은 별도의 관리자 판단과 기록으로 처리한다.

## 13. F-12 관리자 설정과 적용일

| 설정 | 기본값·입력 범위 |
| --- | --- |
| 방·인원 | 이름·개수·정원, 최소 인원 2명 이상·정원 이하 |
| 예약 기간·단위 | 사전 3일, 30분 단위, 최대 120분. 양의 값이며 운영 구간과 호환되어야 함 |
| 공정성 | 중복 비율 50%, 엄격한 초과 적용. 0% 이상 100% 미만; 이용 간격 기본 60분·양수 |
| 기한·신청 제한 | 최초 모집 10분, 보충 10분, 신규 신청 제한 10분. 각각 양수 |
| 운영 | 요일별 공통 구간, 날짜·방 예외, 시설 전체 휴관, 기관 시간대 |

예약 판정에 영향을 주는 설정 묶음은 현재 열린 예약 기간이 끝난 다음 날 00:00 이후로 적용한다. 이미 예약 가능한 날짜의 정책을 일반 설정 저장으로 소급 변경하지 않는다. 각 예약은 자기 이용일에 적용되는 정책을 사용하고, 적용일을 넘겨 이동하면 새 정책으로 전체 검증한다. 새 정책으로 비교할 때 기존 예약을 소급 취소하지 않는다.

예약 가능 여부는 신청 대상 날짜의 정책에 따른 예약 창으로 계산한다. 창 확대는 새 정책 날짜의 예약을 더 일찍 열 수 있으나 기존 예약 내용은 바꾸지 않는다. 저장 전 새로 열리는 날짜와 기존 예약 영향 여부를 보여준다.

방 이름 등 표시 정보는 즉시 수정할 수 있지만 정원·최소 인원·운영 정책은 적용일 규칙을 따른다. 긴급 폐쇄는 별도 영향 처리 절차를 사용한다. 이력 있는 방을 삭제하지 않는다. 기관 시간대는 첫 예약 생성 후 일반 설정에서 바꾸지 않고 별도 데이터 전환 작업 대상으로 둔다.

다른 사람이 수락할 때마다 전원에게 알리지 않는다. 연결된 학생은 슬랙 개인 알림을 기본으로 사용하고, 미연결 학생은 이메일로 필수 알림을 받는다. 로그인 인증 코드는 이메일로 보낸다. 슬랙 장애 시 이메일과 슬랙을 무조건 중복 발송하지 않고 재시도와 웹 상태 확인을 제공한다.

알림 실패로 예약을 취소하지 않는다. 발송 실패·재시도·최종 실패는 관리자가 확인할 수 있어야 한다. 오래된 초대 버튼과 변경 알림에서 최신 상태를 확인할 수 있다. 공개 채널에 참여자 명단을 게시하지 않는다.

## 15. F-14 슬랙 기능

| 기능 | 제공 방식 |
| --- | --- |
| 계정 연결 | 웹에서 발급한 일회용 코드를 본인 슬랙 계정에서 입력 |
| 조회·내 예약 | 날짜별 방 상태와 본인 예약·초대 확인 |
| 신청·초대 | 입력창에서 방·시작·길이·활성 학생 선택. 상대가 슬랙 미연결 상태이면 이메일과 웹으로 초대 응답 |
| 수락·거절 | 개인 알림 또는 내 초대의 버튼 |
| 결과 확인 | 성공·실패 사유·최신 상태·웹 상세 이동 |

슬랙 입력도 웹과 동일한 시간·정원·공정성·권한 검사를 따른다. 접수 응답은 성공과 구분한다. 실제 결과가 나오기 전에 확정으로 표시하지 않는다. 웹은 슬랙이 중단되어도 모든 필수 기능을 제공한다.

슬랙에서 예약 시간 변경·전체 취소·책임 이전·관리자 운영은 웹 상세 화면으로 연결한다. 이는 첫 출시 슬랙 목표인 조회·신청·초대·응답·상태 확인의 범위다. 별도 슬랙 관리자 화면은 제공하지 않는다.

## 16. F-15 기록 보존·기수 종료

개인 식별 가능한 예약·신고·감사 이력의 기본 보존기간은 기수 종료 후 90일까지다. 기관이 확인한 정책을 적용하고 이후 삭제 또는 개인을 식별할 수 없는 통계로 전환한다. 현재 유효한 예약이나 이용 제한 처리가 남으면 먼저 운영 영향을 해결한다.

기수 종료 처리는 관리자가 대상 학생과 예약 영향을 미리 확인한 뒤 일괄 실행한다. 학생을 비활성화하고 F-11의 미래 예약 영향을 처리한다. 새 기수에는 시설·정책 설정만 복사한다. 학생 명단·슬랙 연결·제재를 자동 승계하지 않는다. 정정 요청과 관리자 조치의 사유는 보존기간 안에서 기록한다.

관리자는 기수에 소속시키지 않고 기수 종료·학생 보존기간 정리에서 제외한다. 관리자 계정의 개인 식별 정보는 비활성화 후 90일, 관리자 계정 관리 사건 이력은 사건 발생 후 90일을 기본 보존기간으로 둔다. 그 이후 필요한 운영 기록은 행위자를 익명화하고 이메일 등 식별정보를 제거한다. 기관이 확인한 보존 정책으로 조정할 수 있다. 관리자 행위가 포함된 학생 예약 이력은 해당 예약의 보존 규칙을 별도로 따른다.

## 17. F-16 관리자 계정 관리

### 계정과 권한 원칙

학생·관리자 두 역할만 유지한다. 별도 최고관리자 역할이나 계정별 권한 조합은 첫 버전에 만들지 않는다. **활성 관리자는 다른 관리자 계정을 초대·회수할 수 있는 동등한 운영 권한을 가진다.** 이 권한까지 맡길 수 있는 담당자만 관리자 계정으로 초대한다.

관리자 계정 관리의 실행에는 최근 10분 이내 본인의 이메일 코드 재인증이 필요하다. 목록 조회에는 재인증을 반복 요구하지 않는다. 자기 계정 비활성화는 화면과 서버 모두에서 금지한다. 퇴임자는 후임자의 활성화를 확인한 뒤 다른 관리자에게 회수를 요청한다.

| 계정 구분 | 허용 | 제외 |
| --- | --- | --- |
| 학생 | 예약 신청·초대·수락·본인 예약 관리 | 관리자 화면·API·관리자 계정 관리 |
| 활성 관리자 | 운영 관리, 학생 관리, 다른 관리자 초대·회수 | 관리자 계정으로 학생 예약 참여, 학생 일괄 작업의 대상 |
| 관리자 초대 대기·만료·취소·비활성 | 본인 인증과 유효 초대 확인·수락만 해당 조건에서 가능 | 관리자 업무 기능 |

### 최초 관리자 등록

기관 책임자가 최초 관리자 이메일을 지정하고 배포 운영자가 서버의 일회성 초기 등록 절차를 실행한다. 최초 관리자가 이메일을 인증하고 관리자 초대를 수락해야 활성화된다. 처음 방문한 가입자나 첫 로그인 사용자를 자동으로 관리자로 지정하지 않는다.

초기 등록이 시작되면 일반 초기 등록을 다시 실행해 다른 관리자를 만들 수 없다. 발송 실패·초대 만료는 같은 초기 등록 대상의 재시도로 처리한다. 다른 대상으로 바꾸거나 접근을 복구해야 하면 아래의 별도 복구 절차를 사용한다. 개발용 관리자 seed는 운영 등록을 대체하지 않는다.

### 관리자 계정 관리 화면

목록에는 이름·이메일·계정 상태·초대 만료·최근 변경을 보여주고, 학생 관리와 별도의 메뉴로 제공한다. 관리자 권한이 없는 사람에게 이 목록을 노출하지 않는다.

| 행동 | 입력·조건 | 결과 |
| --- | --- | --- |
| 관리자 초대 | 이름·이메일·사유, 활성 관리자와 최근 재인증 | 24시간 유효한 초대 발급. 이메일 발송만으로 권한 부여하지 않음 |
| 초대 수락 | 초대받은 이메일의 본인 인증, 현재 유효한 초대 | 초대를 수락한 계정만 관리자 활성화 |
| 초대 재발송 | 미수락 또는 만료 초대, 사유·최근 재인증 | 새 24시간 초대 발급, 기존 초대 즉시 무효화 |
| 초대 취소 | 미수락 초대, 사유·최근 재인증 | 미수락 초대 무효화. 늦은 수락으로 활성화되지 않음 |
| 권한 회수 | 다른 활성 관리자 선택, 사유·최근 재인증 | 관리자 계정 비활성화, 기존 업무 접근과 미처리 관리자 변경 차단 |
| 재초대 | 비활성 관리자, 사유·최근 재인증 | 새 초대 발급. 수락 전까지 비활성 권한 유지 |

이미 등록된 학생 이메일을 입력하면 관리자 초대를 거절한다. 학생 CSV나 일반 계정 수정으로 학생을 관리자로 승격하지 않는다. 관리자 회수 시에도 학생으로 강등하거나 학생 예약을 자동 생성하지 않는다.

### 마지막 관리자 보호와 즉시 회수

활성 관리자가 최소 한 명은 남아야 한다. 초대 중인 후임은 활성 인원에 포함하지 않는다. 둘 이상의 관리자가 동시에 상대를 비활성화하려 해도 먼저 처리된 결과 이후 권한을 다시 검사하여 활성 관리자 0명이 되는 결과를 막는다.

회수된 계정은 열어 둔 화면·기존 세션·재전송 요청으로 관리자 업무를 계속할 수 없다. 회수 직전에 이미 완료된 변경은 소급 취소하지 않으며 회수 이후 최종 처리되는 새 변경은 거절한다. 권한이 회수된 관리자가 발급한 미수락 관리자 초대도 취소한다. 다른 활성 관리자가 필요한 초대를 새로 발급할 수 있다.

권한 회수는 즉시 업무 접근을 차단하는 상태 변경이다. 단순히 해당 관리자의 현재 기기에서 로그아웃시키는 기능으로 대체하지 않는다. 초대·수락·회수·복구 사건은 행위자·대상·시각·사유와 함께 기록하고 대상자 및 현재 활성 관리자에게 이메일로 알린다.

### 계정 접근 불가 시 복구

다른 활성 관리자가 있으면 그 관리자가 새 관리자 이메일을 초대하고, 새 계정 수락 후 접근을 잃은 계정을 회수한다. 이메일을 잃은 계정의 주소를 화면에서 즉시 바꿔 다른 사람에게 넘기지 않는다.

모든 활성 관리자가 이메일에 접근할 수 없으면 기관 책임자의 확인을 거쳐 배포 운영자가 서버의 복구 절차로 새 관리자 초대를 발급한다. 공개 웹에 관리자 권한 복구·초기화 버튼을 두지 않는다. 새 관리자가 본인 이메일을 인증하고 수락한 뒤 기존 계정을 정리한다. 복구 사유와 실행 주체를 기록하고 기존·신규 관련 관리자에게 통지한다. 데이터베이스 전체를 과거로 복원하는 절차와는 구분한다.
