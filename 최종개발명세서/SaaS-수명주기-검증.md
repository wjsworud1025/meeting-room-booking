# SaaS 계정 수명주기 구현·검증

기준: 2026-09-30. 코드·합성 DB·로컬 스테이징 검증 완료, 운영 배포 전.

## 확정된 인증 방식

사용자 선택에 따라 이메일 대신 기존 ID 계정 로그인과 현재 비밀번호 재확인을 사용한다. 이전 요청자는 대상 ID를 지정하고, 대상은 `/account`에서 24시간 내 수락한다. 비밀번호 실패 횟수와 잠금을 적용하며 서버에서 인증한 계정 ID와 버전을 DB 함수에 전달한다. 클라이언트의 고객 ID를 신뢰하지 않는다.

## 구현

| 기능 | 동작 |
|---|---|
| 내보내기 | 고객별 JSON ZIP 비동기 생성, 최대 3개 유효 작업, 24시간 만료, 현재 소유자 비밀번호 재확인 후 다운로드. 인증정보·Slack 토큰·세션·내부 작업 payload 제외 |
| 소유권 이전 | 기존 소유자 재확인 → 대상 ID 요청 → 대상 로그인·재확인·수락. 기존 ADMIN 비활성화와 새 ADMIN 활성화, 소유자 교체를 한 트랜잭션으로 처리 |
| 이전 후 접근 회수 | 양쪽 로그인 세션·기존 웹 진입 링크·내보내기 파일 폐기. 다시 로그인한 새 소유자만 관리. 과거 예약·구성원·설치는 보존 |
| 공간 삭제 | 이름 입력과 비밀번호 확인 후 7일 대기. 예약·설치·알림 중지, 내보내기와 기한 내 취소 제공. 합성 DB에서 고객 업무 데이터 삭제·타 고객 보존 확인 |
| 복원 시 삭제 재적용 | 별도로 보존한 삭제 원장을 입력받아 복원 DB의 삭제 고객을 다시 제거하는 라이브러리와 통합 검증 구현 |

## 검증 증거

- `npm run test:saas:web`: 실제 API/제한 DB 역할로 A/B 격리, 타 고객 ZIP 다운로드 거부, 삭제 이름 불일치 거부, 대기/취소, ID 이전, 기존 세션 무효화, 이전 전 ZIP 차단, 7일 경계·삭제 후 고객 B 보존, 과거 복제본에 삭제 원장 재적용 통과. 외부 Slack 전송은 모의 처리한다.
- `npm run build`: TypeScript와 프로덕션 빌드 통과.
- 브라우저의 스테이징 `/account`에서 실제 소유권 이전 메뉴·대상 ID·비밀번호 미입력 시 비활성 버튼을 확인. 실제 고객 소유권을 이전하거나 삭제하지 않았다.
- 승인된 운영 암호화 백업을 네트워크 없는 PostgreSQL 18.6 임시 컨테이너에 복원하여 016/001–005 적용·롤백 후 24개 테이블 지문 일치. 복제본의 앱·워커는 실행하지 않았다.

## 남은 운영 조건

운영 데이터의 자동 영구 삭제는 활성화하지 않는다. 백업과 독립된 삭제 원장 저장소, 확정 삭제 후 최대 30일 백업 만료, 해당 저장소 장애·복원 상황 검증이 필요하다. 현재 원장은 DB 내부에 있고 재적용 도구는 별도 원장을 입력받는 단계다. 환경변수만 켜서는 런타임 검사를 통과하지 못한다.

두 실제 Slack 구성원의 초대·취소·수신 확인은 두 번째 계정이 없어 미완료다. 합성 테스트 결과로 이를 대체하지 않는다. 운영 제한 역할 설치와 고정 주소 설정을 포함한 전환 검증 전 `SAAS_RELEASE_NOT_READY` 차단을 유지한다.
