# SaaS 더미 데이터 격리 검증 결과

검증일: 2026-09-30. 별도 임시 PostgreSQL DB에서 수행. 실제 운영 데이터 변경 없음.

## 데이터

고객 A/B 각각 관리자 1명, 회의실 1개, 클래스 1개, 학습자 2명, 동일 시간대 예약 1건. 고객 간 학습자 이메일을 동일하게 만들어 이메일 기반 혼동도 검사했다. 회원 가입과 공간·회의실 생성은 실제 Next.js API 핸들러를 호출했다. 학습자 명단은 합성 fixture로 넣었고 예약은 실제 업무 명령 execute로 생성했다. HTTP 네트워크나 Slack 인증을 통해 학습자가 예약한 검증은 아니다.

## 결과

| 검사 | 결과 |
|---|---|
| A/B 각자의 시간표·회원·관리자 데이터 조회 | 자기 데이터만 노출 |
| 상대 예약 UUID로 상세 조회 | 양방향 404 |
| 상대 회의실 수정·예약, 상대 구성원 초대 | 거부, 원본 유지 |
| 상대 예약 직접 DELETE | RLS로 대상 0행 |
| 같은 시간·같은 이메일의 고객별 예약 | 독립적으로 성공 |
| URL tenant_id를 상대 고객 ID로 조작 | 로그인 고객 유지 |
| A/B 동시 시간표 조회 10회씩 | 혼입 없음 |
| 알림 작업 payload 및 관리자 데이터 | 상대 예약·구성원 ID 없음 |
| 21개 테이블 무컨텍스트, 교차 FK, 풀 재사용, 정지 고객 | 기존 DB 격리 검사 통과 |

실행: `npm run test:saas:web`, `npm run test:saas`, `npm run typecheck`. 모두 통과. 이번 추가 검사에서 새로운 데이터 혼입 오류는 발견되지 않았다. 테스트 종료 후 생성한 DB와 역할을 정리했다. 다시 실행하면 더미 데이터부터 자동 재생성된다.

검증 범위는 준비된 SaaS 스키마와 비특권 역할을 사용하는 테스트 환경이다. 현재 Railway가 SaaS 격리를 적용했다는 의미는 아니다. Slack 클래스 연결, 실제 DM 발송, 자동 작업자 실행은 아직 미검증이며 해당 전환 작업이 남아 있다.
