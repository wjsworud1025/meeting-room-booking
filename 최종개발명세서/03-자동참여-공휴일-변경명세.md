# 자동 참여·한국 공휴일 표시 변경 명세

적용일: 2026-09-29. 사용자의 이번 변경 요청을 반영하며, 기존 00·01·02 명세의 참여 수락 및 달력 관련 조항보다 우선합니다. 관리자 초대 수락과 책임 이전 수락은 이 변경의 대상이 아닙니다.

## 1. 기능 변경

| 항목 | 변경 후 동작 |
|---|---|
| 신규 예약 | 신청자와 선택한 구성원 모두 즉시 참여. 최소 인원을 충족한 신청을 바로 확정 |
| 구성원 추가 | 초대 실행 시 자동 참여. 상대방에게 수락·거절 버튼을 요구하지 않음 |
| 중복·정원·공정성 | 모든 대상의 활성 상태·제재·시간 중복·정원을 확인하고, 자동 확정 또는 명단 변경 시 같은 모임 간격 검사. 한 명이라도 실패하면 전체 요청 롤백 |
| 내 참여 취소 | 초대된 학생도 시작 전에 본인 참여 취소 가능. 최소 인원 미달 시 기존 보충 기한 적용. 재초대는 기한을 연장하지 않음 |
| 화면 | 수락 인원 대신 참여 인원, 받은 초대 대신 초대된 예약. 관리자 계정 활성화와 책임 이전은 여전히 상대방 수락 필요 |

새 신청 및 추가 초대부터 적용합니다. 과거 예약 명단과 최초 확정 명단을 소급 수정하지 않습니다. 변경 전 생성된 `INVITED` 레코드는 기존 응답 API와 화면으로 처리할 수 있습니다. 현재 개발 DB에 이전 방식의 유효 대기 초대 1건이 남아 있음을 확인했습니다. 기존 기록에 대한 일괄 자동 전환은 실행하지 않았습니다.

## 2. 시스템 변경

`booking.create`와 `booking.invite`는 기존 `inviteeIds` 입력 계약을 유지합니다. 서버는 전체 대상을 검증한 뒤 `reservation_members.status='ACCEPTED'`, `responded_at=판정시각`으로 저장합니다. 이 값은 실제 의사표시 시각이 아니라 자동 참여 처리 시각입니다. 같은 트랜잭션에서 `settle`, 최초 확정 명단 저장, 개인 시간 점유, 알림 등록을 수행합니다. 별도 서비스나 DB 테이블을 추가하지 않습니다.

이전 초대 응답의 중복 처리, 재초대 세대 검사, 책임 이전 요청 및 관리자 온보딩은 유지합니다. 신규 예약에는 모집 대기 단계가 발생하지 않지만, 이전 예약 호환을 위해 HOLDING 상태와 관련 서버 정책 필드를 유지합니다. 관리자 화면에서는 신규 예약에 사용하지 않는 최초 모집 기한 입력을 숨깁니다.

## 3. 날짜 선택과 휴일

전체 시간표, 예약 신청·변경, 관리자 휴관·예외 개방·예약 변경·정책 적용일에서 같은 날짜 컴포넌트를 사용합니다. 직접 날짜 입력과 월별 달력을 제공하며 일요일·공휴일은 빨강, 토요일은 파랑으로 표시합니다. 날짜의 공휴일명·대체공휴일명은 버튼의 접근성 이름과 선택일 아래에도 표시합니다.

2026·2027년 검토된 자료를 앱에 포함합니다. 네트워크나 API 키 없이 표시됩니다. 다른 연도는 ‘공휴일 자료 없음’을 표시하며 평일로 확정하지 않습니다. 임시공휴일 등 추가 지정은 자료 업데이트가 필요합니다. 휴일 이름 표시만으로 예약을 막거나 기존 예약을 취소하지 않습니다. 실제 시설 휴관은 관리자 휴관 설정으로 적용합니다.

## 4. 검증

정책·공휴일 단위 검사 10개, PostgreSQL 통합 검사 24개가 통과했습니다. 통합 검사에는 자동 확정, 모든 참여자의 즉시 점유, 추가 초대 일부 충돌 시 전체 롤백, 동일 모임 제한, 비활성 대상 거절, 재보충 기한 유지가 포함됩니다. 독립 브라우저 2개에서 신청 직후 상대방 예약이 확정되고 수락 버튼이 없는 것과 취소 동기화를 확인했습니다. 달력에서는 2026년 10월 5일 대체공휴일 선택 및 관리자 드로어 내부 Escape 동작을 검사합니다.
