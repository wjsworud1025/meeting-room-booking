# 공휴일 자동 갱신·관리자 보정

2026-09-29 적용. 03 변경명세의 ‘공식 API 미연결, 정적 자료만 제공’ 설명을 대체합니다. API 연결 코드는 구현했으며 실제 서비스키를 입력하기 전에는 외부 조회하지 않습니다.

## 관리자 사용 순서

1. **시설·운영 설정 → 한국 공휴일 관리**에서 연도별 휴일과 최근 조회·성공 시각을 확인합니다.
2. 공식 발표가 데이터보다 빠르면 **휴일 추가**에서 날짜, 이름, 발표 링크, 변경 사유를 입력합니다. 이미 있는 날짜는 **수정**합니다.
3. 잘못 표시된 휴일은 **휴일 표시 제외**로 숨깁니다. **관리자 수정 해제·원본 복원**은 수동 보정만 제거합니다.
4. **영향 예약·휴관 검토**에서 해당 날짜의 전체 시설 예약을 확인한 뒤 휴관 적용 여부를 결정합니다. 휴일 등록 자체는 예약을 변경하지 않습니다.
5. 공식 갱신으로 변경된 미래 날짜는 **운영 검토 대기**에 남습니다. 예약을 검토한 후 **확인 완료**로 표시합니다. 이 버튼은 휴관을 적용하지 않습니다.

## 실제 API 연결

[공공데이터포털 한국천문연구원_특일 정보](https://www.data.go.kr/data/15012690/openapi.do)에 활용 신청한 후 서버의 `.env.local`에 아래 항목을 추가합니다. 키는 채팅이나 클라이언트 코드에 넣지 않습니다.

```dotenv
HOLIDAY_API_KEY=발급받은_서비스키
RUN_JOBS=true
```

서버를 다시 시작한 후 **지금 동기화**를 누릅니다. 실제 제공기관 조회가 성공해야 ‘최근 성공’ 시각이 생성됩니다. 인증키가 없거나 작업 실행이 꺼져 있으면 버튼을 비활성화하고 사유를 표시합니다. 키를 입력하지 않은 현재 환경에서는 기본 자료와 관리자 수동 보정을 사용합니다.

## 실행·데이터 규칙

| 항목 | 동작 |
|---|---|
| 자동 조회 | KST 기준 올해·다음 해, 6시간마다. 기존 단일 서버의 작업 루프 사용 |
| 수동 동기화 | 작업을 즉시 등록하고 기존 작업 루프가 처리. 같은 작업이 진행 중이면 중복 생성하지 않음. 최근 시도 후 1분 제한 |
| 외부 API | `getRestDeInfo`, 연도별 최대 1,000건 조회. 서버 전용 키 사용, 12초 제한. 키를 로그·오류에 노출하지 않음 |
| 검증 | XML/JSON 구조, 성공 코드, 전체 행 수, 연도, 유효 날짜·명칭·휴일 여부 검사. 빈 자료·페이지 누락·오류 응답 거절 |
| 저장 | 두 연도 조회가 모두 성공하면 한 트랜잭션으로 저장. 하나라도 실패하면 기존 두 연도와 성공 시각 유지 |
| 수동 보정 | 공식 원본과 별도 보관. 동기화 후에도 보정이 우선. 버전 검사와 감사 이력으로 오래된 편집 차단 |
| 변경 검토 | 실효 휴일 목록의 변경 날짜 누적. 다음 조회에서 변경이 없어도 미확인 날짜를 지우지 않음. 지난 날짜는 다음 성공 조회 시 정리 |
| 실패 처리 | 기존 작업 재시도 정책: 1·5·15분 간격, 최대 4회. 화면에 실패 코드와 기존 자료 유지 상태 표시 |
| 달력 반영 | 서버 저장 자료 조회, 브라우저 내 10초 캐시. 활성 화면에서 15초 주기로 재확인. 같은 화면의 수동 변경은 즉시 갱신 요청 |

DB 마이그레이션 `002_holidays.sql`은 `holiday_years`, `holiday_overrides`, `holiday_sync` 3개 테이블과 `HOLIDAY_SYNC` 작업 종류를 추가합니다. 기존 업무 데이터는 삭제하지 않습니다. 초기 14개 테이블에 3개 운영 테이블이 추가되어 총 17개입니다. 기본 2026·2027년 자료는 최초 정상 동기화 전과 지원 자료가 없는 경우에 사용합니다. 관리자 화면의 키 설정 여부는 서버에서 계산한 참/거짓만 제공하며, 키 값은 반환하지 않습니다.

## 검증 및 한계

- 공식 응답 형태의 테스트 데이터를 사용해 XML/JSON 파싱, 빈 값·누락·비정상 응답을 검증합니다.
- 실제 PostgreSQL에서 수동 보정 보존, 전체 갱신 롤백, 권한·버전 검사, 6시간 주기, 중복 방지, 검토 완료를 검사합니다.
- 브라우저에서 수동 등록→달력 표시→영향 예약 확인→표시 제외→원본 복원을 검증하며 테스트 자료는 정리합니다.
- 현재 서비스키가 없어 **실제 제공기관 인증·실시간 응답은 미검증**입니다. 정부 발표와 제공기관 데이터 반영 사이 지연은 이 시스템에서 보장할 수 없으므로 수동 보정 기능을 병행합니다.
- 앱 서버가 꺼져 있는 동안에는 자동 조회하지 않습니다. 다시 실행되면 지난 예정 시각을 확인해 작업을 등록합니다. 별도 외부 스케줄러는 사용하지 않습니다.
