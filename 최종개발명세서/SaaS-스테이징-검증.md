# SaaS 스테이징 최종 검증 결과

검증일: 2026-09-30

## 판정
현재 가능한 스테이징 검증 범위는 통과했다. 실제 Slack 구성원 2명이 브라우저에서 예약을 완료하는 검증은 별도 계정이 없어 미실시했다. 이를 완료로 표기하지 않는다. Railway 운영 전환은 별도 단계다.

## 실제 Slack·브라우저 검증
1. 전용 설치 링크 → Slack OAuth 설치 → 테스트 고객과 워크스페이스 연결 확인.
2. Socket Mode 앱 홈 표시 → 예약하기 클릭 → 추가 코드 없이 학습자 웹 시간표 진입 확인.
3. 30분 선택 유지, 최소 인원 미달 시 신청 차단, 가상 비-Slack 구성원 검색 제외, 마감 21:00 시작 시 30분만 허용 확인.
4. 학습자 세션의 관리자 URL 진입 시 학습자 화면으로 복귀, 고객 관리자 ID 로그인 및 관리자 화면 진입 확인.
5. 서버 명령 경로에서 본인+가상 참여자 예약 생성·취소 성공. 고객별 작업 claim/runTask를 통해 본인에게만 DM 2건 발송했고 Slack 메시지 화면에서 실제 수신 확인.

## 격리 및 회귀 검증
- npm test: 19개 파일, 121개 테스트 통과.
- test:saas: 기존 데이터 보존·21개 테이블 RLS·교차 고객 읽기/쓰기·고객 중지·풀 재사용·권한 있는 런타임 거절 통과.
- test:accounts: 기존 ADMIN 귀속·해시 비밀번호·최초 변경·세션 폐기·로그인 잠금·미활성 고객 접근 차단 통과.
- test:saas:web: 실제 API 핸들러에서 고객 A/B 회의실·구성원·동시간 예약·조회/수정/삭제 차단·20개 동시 조회 통과.
- Slack/worker 통합: 설치 링크 재사용 및 워크스페이스 탈취 차단, 고객별 토큰·수신자, 동시 작업 claim, 타 고객 예약 payload 및 전송 직전 고객 중지 차단 통과. 이 검사의 Slack 전송은 모의 처리다.
- 최종 빌드와 git diff --check 통과.

## 발견 및 수정
SaaS에서는 서버가 기존 이메일/Slack 직접 로그인을 차단하지만 로그인 화면에는 해당 기능이 남아 있었다. SaaS 관리자 화면은 ID 로그인만 제공하고 구성원 로그인 화면은 Slack 앱에서 시작하도록 안내한다. 기존 비-SaaS 모드의 로그인 기능은 유지한다.

## 테스트 자원 및 안전 상태
- 앱: 회의실 예약 테스트 / A0C5FA7934N. 운영 앱 A0C4QRGDJ0P와 별개.
- 워크스페이스: 연결 테스트 / T0C4QQ11V2B.
- 별도 로컬 DB, 웹·인증·작업용 제한 역할 3개. 운영 데이터 복사 없음.
- npm run saas:staging:prepare: 새 로컬 DB 생성 전용. 기존 설정 존재 시 중단.
- npm run saas:staging:start: 테스트 DB·역할·HTTPS·운영 앱 혼용 검사. 자동 마이그레이션 없음.
- 연결키와 테스트 관리자 자격증명은 Git 제외 로컬 파일에 보관.
- 테스트 예약은 취소됨. 가상 참여자 발송 작업 4건은 FAILED로 보관해 자동 재시도 방지. 전역 RUN_JOBS=false 유지.
- HTTPS는 임시 Cloudflare 터널이다. 운영 주소로 사용할 수 없다.

## 운영 전환 전 남은 조건
1. 실제 구성원 2명으로 브라우저 예약·초대 검증.
2. 운영 백업, 데이터 이관 및 제한 DB 역할 적용, 롤백 절차 리허설.
3. 공휴일 등 공유 작업과 다중 프로세스 운영 방식 확정. 현재 SaaS 작업기는 고객별 NOTIFY를 처리하며 모든 기존 작업 유형의 운영 이관이 끝난 상태는 아니다.
4. 고정 HTTPS 주소와 운영 앱 연결 검증 후 출시 차단 해제. 현재 start-railway.mjs의 SAAS_RELEASE_NOT_READY 차단은 유지한다.


## 2026-09-30 최종 후속 검증

이 절은 앞선 중간 점검의 미완료 목록을 갱신한다. 공휴일 공유 작업(004), 내보내기·ID 기반 소유권 이전·삭제 대기/취소(005), 비특권 역할 설치·검사와 별도 워커를 구현했다. 실제 API·DB의 고객 A/B 격리와 수명주기 통합 검사를 통과했다. 영구 삭제는 합성 DB에서만 검증했고 운영 실행은 차단한다.

승인된 최신 암호화 백업 railway-1790744899443은 24개 테이블(업무 274행, 마이그레이션 15행, import 1행)과 공휴일 시퀀스를 포함한다. 네트워크 없는 PostgreSQL 18.6 컨테이너에서 016 및 후보 001–005 적용·롤백 후 24개 테이블 지문이 일치했다. 설치 토큰의 현재 키 복호화도 확인했다. 임시 컨테이너와 SSH 키 등록은 정리했다. 운영 원본은 변경하지 않았다.

운영 전환에는 별도 삭제 원장 보존·백업 30일 만료 검증, 운영용 제한 역할 적용, 두 실제 Slack 구성원 검증이 남아 있다. 현재 두 번째 Slack 계정이 없어 모의 검증으로 대체 완료하지 않는다. 상세 기준은 [수명주기 검증](SaaS-수명주기-검증.md)과 [운영 전환 절차](SaaS-운영전환-복구절차.md)를 따른다.
