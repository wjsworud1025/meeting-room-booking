# 로그인 ID·기존 데이터 귀속 구현 현황

2026-09-30 / codex/saas-data-isolation

## 적용 범위

- 로컬 DB의 기존 활성 ADMIN을 `hyundai_1st` 로그인 계정과 연결했다. 기존 member/예약/Slack ID는 변경하지 않았다. 현재 전체 단일 고객 데이터의 소유권은 identity.legacy_owner에 기록한다.
- 요청한 임시 비밀번호를 salted scrypt 해시로 저장했다. ID 로그인 후 15분짜리 변경 전용 세션을 발급하며 비밀번호 변경 전 예약·관리자 API는 거부된다. 최초 변경 후 일반 세션은 8시간, 로그인 유지 선택 시 최대 30일이다.
- 새 비밀번호는 10~128자. 비밀번호 변경 시 해당 ID 계정의 모든 세션을 서버에서 삭제한다. 기존 Slack/이메일 로그인은 호환 유지하며 독립된 인증 방식이다.
- 신규 ID는 영문·숫자·밑줄 4~32자, 대소문자 구분 없이 중복 차단한다. hyundai_1st는 공개 가입으로 선점할 수 없다. 신규 사용자는 자신의 비밀번호를 지정한다. 다른 신규 사용자에게 공통 임시 비밀번호를 부여하지 않는다.
- 연속 로그인 실패 5회 시 10분 잠금, 세션 토큰의 해시 저장, CSRF 출처 검사, 가입/IP 요청 제한을 적용했다.

## 경로

| 경로 | 기능 |
|---|---|
| /admin/login | ID·비밀번호 로그인. 기존 Slack/이메일 로그인 선택 가능 |
| /register | 신규 관리자 ID 생성 |
| /account | 내 계정 상태, 비밀번호 변경, 로그아웃 |
| /account/password | 최초 임시 비밀번호 변경 및 이후 변경 |

## 신규 계정의 접근 범위

신규 가입은 PENDING이며 예약 시스템 ADMIN member를 생성하거나 기존 데이터와 연결하지 않는다. 계정 로그인/비밀번호 변경/로그아웃만 가능하다. 임의 ID 또는 URL로 기존 예약·관리자 API에 접근해도 서버에서 거부한다. 신규 고객의 실제 독립 공간 생성·예약 사용은 앞서 문서화한 인증/API/작업자/RLS 런타임 전환 완료 후 활성화한다. 현재는 완성된 멀티테넌트 서비스가 아니다.

SaaS 이관 후보가 legacy_owner.account_id를 첫 고객의 owner_account_id로 복사하므로 로그인 계정 ID와 데이터 소유권이 이어진다. 비밀번호 해시는 identity에 보존하며 사본을 만들지 않는다. 신규 계정의 tenant 자동 생성 및 인증 이메일 검증/계정 복구는 미구현이다. 비밀번호 분실 복구를 완성하기 전 공개 서비스 출시하지 않는다.

## 실행과 검증

```powershell
npm run db:migrate
# INITIAL_ADMIN_PASSWORD를 작업 환경에 넣은 뒤 실행. 실행 후 환경 변수 제거.
npm run account:bootstrap -- hyundai_1st
npm run test:accounts
npm run test:saas
```

bootstrap은 기존 연결이 같으면 아무것도 변경하지 않으며 비밀번호를 재설정하지 않는다. 다른 소유자가 있거나 활성 ADMIN이 하나가 아니면 중단한다. 소유자 등록 시 비밀번호를 커맨드 인자/로그에 출력하지 않는다.

통합 테스트는 별도 임시 DB에서 기존 ADMIN 연결, ID 중복, 해시 저장, 변경 강제, 토큰 위조 거부, 세션 폐기, 잠금, 신규 계정 접근 차단, SaaS 이관의 OWNER UUID 보존을 검증한다.

운영 Railway에는 이번 변경을 배포하거나 계정을 생성하지 않았다. 운영 적용 시 스키마 추가 → bootstrap(소유자 ID/초기 암호는 승인된 운영 환경에서 주입) → 앱 배포 순으로 수행한다. 임시 암호를 소스·배포 이미지·환경 변수에 영구 보관하지 않는다.
